Part 1 — Learn these 7 things only (1 h)

  1. IP address = the computer's address on the network
  2. Port = the door number for one service (web: 80/443)
  3. Subnet / CIDR = a group of addresses (192.168.1.0/24)
  4. Gateway = the exit door to other networks
  5. Route = the path the packet is told to take
  6. TCP = reliable (web, SSH); UDP = faster, less checking (DNS often)
  7. Private IP (10.x, 192.168.x) stays inside; public IP is on the internet

In notes/2026-08-17.md: What is an IP? What is a port? Why can ping work but a website still fail?

Part 2 — Hands-on (2 h)

After each command write one line: "This shows me …"

ip addr            # my IP
ip route           # my gateway
ping -c 4 127.0.0.1
ping -c 4 8.8.8.8  # if blocked, tell mentor and skip
ss -lntup          # what is listening (find port 80 / Nginx)
curl -v http://127.0.0.1/

If Nginx is not running: sudo systemctl start nginx (ask if stuck). Optional: traceroute 8.8.8.8 if available.

Part 3 — Small labs (1.5 h)

  1. CIDR practice: for 2 mentor-given CIDRs write network address, broadcast address, and roughly how many usable hosts. Explain /24 in your own words.
  2. Path to Nginx: write the request path in simple steps (curl → 127.0.0.1:80 → process from ss → Nginx answers).
  3. Two error words: cause or observe both — connection refused (nothing listening) and timeout (packets don't come back). One example of each in notes.

Optional, only if time and mentor says OK: sudo tcpdump -i lo -n -c 20 tcp port 80 while curling.

Part 4 — Show your work (30 min)

Show: IP + gateway, the ss line for the web service, CIDR answers, path-to-Nginx notes, refused vs timeout. Be ready for: What does /24 mean? Refused vs timeout? Why can ping work but HTTP fail? What does a gateway do? One TCP and one UDP example.
