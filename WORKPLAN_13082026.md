## Part 1 — Bash script (about 1 hour)

### First, understand 4 small things

1. A program finishes with a number: `0` = success, anything else = problem.  
2. `"$1"` means "the first thing the user typed after the script name".  
3. Always wrap variables in quotes: use `"$name"`, not `$name`.  
4. `curl` can check a website.

Try these in the terminal and watch what happens:

```bash
true;  echo $?     # prints 0
false; echo $?     # prints 1
name="a b"
echo $name         # looks wrong
echo "$name"       # looks right
```

### Now write the script

Make a file `scripts/healthcheck.sh`. It should:

- Take a website URL that the user types  
- Check if the website works  
- Print the time, the status, and how long it took  
- Finish with `0` if the site is OK, or another number if not  
- If the user forgets the URL, print a short message and stop  

Make it runnable:

```bash
chmod +x scripts/healthcheck.sh
```

### Test it (write down what you see)

```bash
./scripts/healthcheck.sh                      # should politely say "give me a URL"
./scripts/healthcheck.sh http://127.0.0.1/    # should show status + time
echo $?                                        # 0 if the site is OK
```

Ask yourself: *Did it do the right thing each time?* If yes, you're done with Part 1.

> Not today: cron, timers, mounts. Those come in Week 3. Don't worry about them.

## Part 2 — Git basics (about 1.5 hours)

Git = a safe way to save your work with history.

### Step 1: don't save secrets

Add a `.gitignore` file so passwords/keys never get saved:

```text
.env
*.pem
```

### Step 2: make a branch and save your work

```bash
git checkout -b day02-work
git add scripts/healthcheck.sh
git commit -m "Add healthcheck script"
```

Make **2 or 3 small commits** as you go. Each commit = one small finished thing.

### Step 3: try a merge conflict (ask mentor to help set it up once)

A conflict happens when two changes touch the same line. You will:

1. See the `<<<<<<<`, `=======`, `>>>>>>>` marks  
2. Pick the correct final text and delete the marks  
3. Save, then `git add` and finish  

Write 2–3 lines in your notes about what happened.

### Step 4: undo safely

```bash
git revert <commit-id>
```

This makes a new "undo" commit. It is safe. (Avoid `reset --hard` on shared work — ask why.)

### Step 5: write a short README

Just answer:

- How do I run the healthcheck?  
- What does `0` vs other numbers mean?  
- What should never be saved in Git?

### Check your Git

```bash
git log --oneline
git status
```

You want to see clear commits and no secret files.

Learn other git related commands.
